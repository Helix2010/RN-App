# UI 与交互规范

本规范定义体验层必须满足的行为合同。品牌视觉可以替换，状态、可访问性和反馈规则不能随意替换。

## 1. 设计系统层次

设计系统由低到高分为四层：

1. **Foundation tokens**：原始色板、字体族、间距阶梯、圆角、阴影、z-index、动效曲线。
2. **Semantic tokens**：`surface.primary`、`text.muted`、`feedback.danger`、`border.focus` 等有语义的令牌。
3. **Primitives**：Text、Box、Stack、Icon、Pressable、Divider；无业务语义。
4. **Patterns**：Button、Input、ListItem、Dialog、Toast、PageState、FormField；包含状态和可访问性。

feature 只能使用 semantic tokens 与公开组件，不直接引用原始色板。主题至少支持 light/dark/system，并允许品牌主题在 semantic 层映射，不复制组件实现。

设计与代码 token 使用同一命名表，生成 TypeScript 类型；不接受从设计稿逐页复制 `#RRGGBB`、margin 或 fontSize。

## 2. 布局与视觉基线

- 以 4pt 网格组织间距，常用阶梯由 token 定义；不得为了“像素对齐”产生大量 13、19、27 等孤立值。
- 页面根容器必须处理 safe area、键盘、横竖屏策略和系统栏。
- 文本必须使用语义排版级别，如 `display`、`title`、`body`、`caption`；不得把字号与行高散落在页面。
- 动态字体放大不能截断关键文案或遮挡操作。必要时布局换行/滚动，不以禁用字体缩放解决。
- 图片必须声明尺寸、裁剪方式、占位与失败状态；远程图片禁止无上限原图解码。
- 阴影、模糊与透明叠层需验证 Android 表现和性能，不假设 iOS 效果跨平台一致。
- 全屏页、底部弹层、系统 Dialog 的使用场景固定，禁止仅凭视觉喜好混用。

## 3. 组件合同

每个公共组件必须说明：

- props 与默认值；
- normal / pressed / focused / disabled / loading / error 状态；
- VoiceOver/TalkBack 的 role、label、hint、state；
- 暗色、高对比度、字体放大、RTL（若产品支持）的表现；
- 是否受控、事件是否幂等、异步期间是否可重复触发；
- 截图示例与交互测试。

触控目标建议不小于 iOS 44pt、Android 48dp；视觉区域可以更小，但 hitSlop 不能与相邻目标冲突。

## 4. 页面状态模型

每个依赖异步数据的页面必须显式设计以下状态，不得只实现“有数据”：

| 状态              | 用户看到什么                 | 允许操作                 |
| ----------------- | ---------------------------- | ------------------------ |
| initial-loading   | 首屏骨架或明确进度           | 可取消的流程允许返回     |
| refreshing        | 保留旧内容并显示轻量刷新     | 页面仍可读，冲突操作受控 |
| content           | 正常数据                     | 正常操作                 |
| empty             | 原因、下一步和主操作         | 创建/调整筛选/返回       |
| recoverable-error | 人能理解的信息与重试         | 重试、返回、联系客服     |
| offline-stale     | 缓存内容、离线标记与时间     | 可读；高风险提交禁用     |
| permission-denied | 权限原因与价值说明           | 再次申请或前往设置       |
| blocked           | 仅用于不可兼容/强更/合规阻断 | 只提供明确恢复路径       |

骨架屏应近似真实结构，避免布局跳跃；无法估计时使用进度提示，不做永久旋转器。

## 5. 反馈与错误文案

- 字段可修复错误贴近字段显示；跨字段业务错误显示在表单摘要或页面级区域。
- Toast 仅用于无需用户决策、不会丢失的重要程度较低的瞬时反馈。
- Dialog 只用于高风险确认或必须立即决策，不用于普通成功提示。
- 错误文案包含“发生了什么 + 用户能做什么”，不向用户显示堆栈、HTTP 状态码或内部错误码。
- 工程错误码、traceId 可放在“问题详情/复制诊断信息”中，方便客服定位。
- 成功反馈不应打断自然结果；若页面结果已清楚变化，不重复弹成功框。

## 6. 异步交互

- 提交按钮触发后立即进入 submitting；是否禁用由业务幂等性决定，但同一 intent 不得并发提交。
- 页面离开或查询条件变化时取消已失效请求；迟到响应不能覆盖新状态。
- 搜索输入防抖只影响请求，不延迟文本本身；响应按 query key 隔离。
- 乐观更新必须有回滚快照、冲突策略和失败反馈；资金、权限、安全类操作默认不乐观。
- 进度超过可感知阈值时显示反馈；长任务应支持后台化、重试或恢复，不能把用户锁在前台。

## 7. 导航与手势

- 一个屏幕只有一个明确主操作；次操作不得与主操作抢占视觉层级。
- 返回行为必须可预测：先关闭临时层，再退出页面；有未保存内容时提示保存/放弃。
- 手势操作必须有可发现的等价按钮，尤其是删除、归档等破坏性动作。
- Tab 保持各自导航栈；重复点击当前 Tab 的回顶/刷新行为需全局一致。
- 深链、推送点击和应用内导航必须收敛到同一 typed intent，不在各 SDK 回调中散落跳转。

## 8. 权限与隐私体验

权限请求遵循：业务触发 -> 应用内说明 -> 系统弹窗 -> 成功/拒绝/永久拒绝处理。

- 不在冷启动批量索取权限。
- 应用内说明必须与马上发生的操作相关，不使用诱导性文案。
- 用户拒绝后保留不依赖权限的功能；永久拒绝时提供设置页入口。
- 相机、相册、定位、通知、蓝牙等分别设计受限模式，不用一个通用弹框掩盖差异。

## 9. 动效与触觉

- 动效用于解释层级、连续性和结果，不作为等待的装饰。
- duration/easing 使用 token；支持系统“减少动态效果”，关闭非必要位移和视差。
- 动画必须可中断、可重入，不能阻塞真实状态更新。
- 触觉反馈与事件语义一致：选择、成功、警告、失败；高频列表操作禁止滥用。

## 10. 多语言与内容

即使首期只有中文，也应使用消息 key 管理产品文案，以便统一术语和后续国际化。禁止拼接含变量的自然语言句子；日期、数字、货币、复数和时区由格式化层处理。服务端 message 仅作诊断或兜底，不直接成为核心用户文案。

## 11. 验收矩阵

每个页面至少验证：

- iOS 与 Android 各一个真实设备或等价构建；
- 小屏与主流屏宽、light/dark、字体 100% 与最大支持档位；
- loading/empty/error/offline/content；
- VoiceOver/TalkBack 的焦点顺序与控件名称；
- 慢网、超时、重复点击、返回中断、进程重启；
- 无截图溢出、透明点击层或被键盘遮挡的主操作。

公共组件使用组件目录保存可视案例，并做确定性截图回归；关键流程使用 Maestro E2E，避免对每个像素都依赖 E2E。
