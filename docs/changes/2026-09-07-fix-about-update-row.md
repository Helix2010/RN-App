# 关于页"检查更新"行：标题写死、OTA 已下载时没有文案

日期：2026-09-07

## 现象

真机装了 1.2.9 (23) 后，用户在「关于」页点那一行检查更新，看到的始终是"已是最新版本"，
以为 OTA 没发出去。服务端 rev 3 其实已经发布并被设备静默下载、下次启动生效。

## 原因

`about-screen.tsx` 里这一行的标题被写死成 `settings.upToDate`（"已是最新版本"），
还没点就这么显示；值的映射只有 检查中 / 出错 / 已是最新 / 检查更新 四种，
手动检查返回"OTA 已下载待重启"时落到"检查更新"。设置页那一行有 OTA 待应用的
映射，关于页漏了，两处各写一份导致不一致。

另外两处都只看这次手动检查的结果。启动时的静默检查把更新下载好后，用户没点之前
这一行仍显示"已是最新版本"，和事实相反。

## 修复

- 新增 `src/features/updates/update-check-row.ts` 的 `updateCheckRowValue`，设置页和关于页共用。
- 值文案直接反映运行时的 `otaResult`：只要 OTA 状态不是"当前已最新"（ready / downloading /
  error / rollback / 被远程关闭……），就显示对应文案；有整包新版本时显示版本号；
  检查中 / 出错优先。
- 关于页标题改为"检查更新"。

## 验证

- `update-check-row.spec.ts`、`about-screen.spec.tsx`（新增"已下载待重启"用例）。
- 模拟器：运行 rev 3 时下载 rev 4，设置页与关于页均显示"更新已下载，将在下次启动时自动应用"；
  重启后显示"已是最新版本"。

## 追加：应用身份纳入心跳指纹（同日）

排查中发现服务端曾把 OTA 包的应用身份改写成 APK 包名（RN-Server 87e88d7 已修）。
装上修复后的 OTA 包，设备的 `X-Application-ID` 会从包名换回租户配置的 `dex-mobile`，
但心跳指纹里没有应用身份，同一份上报会被节流 30 分钟，服务端这段时间看到的还是旧身份。
`heartbeatFingerprint` 现在带上 `appRuntime.applicationId`，身份一变立即重新注册并心跳。
