服务端已生成本租户的签名密钥，签名者地址 `0x9269Ca361b9F0427ac883e89cD5B5fe113BBAD17` 钉进 `tenants/anyfun/tenant.json`，`REQUIRE_BOOTSTRAP_SIGNATURE` 翻成 true。

## N23：移除助记词复制入口

系统剪贴板是应用外的共享缓冲区：同设备任何应用能读，第三方输入法能读，Android 的剪贴板历史和跨设备同步会把它带走。定时抹除只缩短窗口，改变不了"助记词离开了这个应用"这件事，而助记词泄露是不可逆、全部资金、永久有效的。

抄写是慢，但慢正是这一步该有的样子。代码里留了一段注释说明不要加回来。

## N25：未备份的账户不给收款码

收款是"把钱放进一个只有这台设备能打开的抽屉"。助记词还没抄下来之前，任何一次换机、清数据、系统作废密钥，这笔钱就再也拿不回来了——而用户当时不会知道。

只挡自托管账户：外部钱包的恢复材料不在我们手上，也不该由我们判断。

## 0c-2：签名免验证时长交给用户

评审记过 5 分钟太长——拿到一台刚解锁过的设备的人有五分钟可以随便签名；而开通预测一次要签三笔，降到 0 又会连弹三次。

默认 60 秒，安全中心四档可选：每次都验证 / 1 分钟 / 5 分钟 / 15 分钟。金库拿的是**函数**不是数字，因为它在启动时构造一次——传死数字会让改了设置的人要重启才生效。

## N10：不禁止，但数得出来

设备没有锁屏或生物识别时，金库的身份验证判为"不可用"而放行。**继续放行**：把人锁在门外换不来安全，他只会换一个更糟的地方放助记词。

- 上报里加 `screenLock` 三态信号。
- 管理端安装列表支持按任意完整性信号筛：`integrity.screenLock=no` 之类，取值 yes / no / unknown。
- **unknown 单独一档**：老版本没上报和报了 false 是两件事，折在一起统计出来的数就是假的。
- 筛选走 `JSON_EXTRACT` 而不是把整段拉出来在 Go 里过滤，设备数上来之后那会变成全表扫。字段名走白名单——它会拼进 JSON 路径。

## N17：x-admin-key 绑定来源

这把密钥长期有效、没有账号绑定，谁拿到谁就是管理员。actor 早已绑死在配置里，这次补上来源 IP（`ADMIN_API_ALLOWED_IPS`，CIDR 或裸 IP）。

**一个前提不能绕过**：gin 默认信任所有代理，来源地址由 `X-Forwarded-For` 决定，也就是请求方自己说了算。那种情况下的 IP 白名单看起来像一道门、实际谁都能推开，比没有门更糟——它会让人以为这件事做完了。所以配了白名单却没配 `TRUSTED_PROXIES` 时**服务端拒绝启动**。

顺带：`SetTrustedProxies` 让登录限流也按真实来源计数，在此之前它同样是可绕过的。

**部署上还要做一件事**：在生产 env 里设 `TRUSTED_PROXIES`（网关所在网段）和 `ADMIN_API_ALLOWED_IPS`。不设的话这条通道维持现状，不会中断任何自动化。
