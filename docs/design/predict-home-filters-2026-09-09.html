01

首屏结构：默认"全部"

进页就是全站热门。筛选压成两行加一行可选的二级，运营位（精选、榜单、周期市场）只在"全部 + 交易中 + 未搜索"这一种视图出现，一旦收窄分类就让位给列表。下图是默认视图的首屏与向下滚动后的第二屏。

A一级分类：横滑 chip，"全部"固定首位、默认选中；末尾"更多 ▾"打开 188 个标签的面板。
B视图 / 排序：两个下拉 chip，非默认值用主色描边提示。
C收藏开关：右对齐，开启后只看收藏并忽略分类与排序。
D精选：运营 hero 位，吸附轮播海报卡，下一张露出 32dp。
E榜单：四个榜合并为一个区块，tab 切换，单列完整标题。
F钉住的悬浮条：只钉一级行，二级与下拉不钉。
G周期市场：系列卡；有报价才画涨 / 跌，无报价一行灰字。
H列表标题带总数；40 条一页，到底自动翻页。
02

推荐位怎么展示

推荐位有两种来源：平台运营在策展接口里给事件排的位置（hero / highlight / normal 三个区），以及 App 本地从当前列表算出的两个榜（高概率、今日热门）。它们在页面上落成两个区块，职责分开：精选负责"让一件事被看见"，榜单负责"把一批事排个序"。两者都不承担下单，下单留给卡片详情和周期市场的期卡。

出现条件：一级 = 全部 · 视图 = 交易中 · 收藏关闭 · 没有搜索词。任一条件不满足，两个区块整体收起，屏幕让给列表。这条规则和网页版一致（`type=all` 才有 curation），也避免了"在 Weather 下看到 Politics 的精选"这种错位。

数据
策展 hero 区，按运营位次 featuredOrderHero 排；最多 5 张
容器
1 张：单卡满宽；≥2 张：SnapCarousel fullWidth peek=32 showDots，与首页"热门预测"同一手感
卡片
白底 $surface，1dp $borderColor，圆角 16；固定结构，不随结果数量变高
图片
全宽 16:9，cover；左上角标"✦ 精选 · 分类"（55% 黑底白字），右上收藏
标题
两行省略，`SectionTitle` 15/700
结果行
只展示首个结果：名称 · 概率 · compact Yes/No；无报价时不画按钮，写"暂无报价"
脚注
"共 N 个结果 · 成交 $x"，其余结果点卡进详情看
交互
整卡进详情；Yes/No 直接开下单面板；"查看全部 ›" 进入全部视图列表

2.2 榜单（highlight / normal 区 + 本地榜）

榜单
热门精选突发高概率今日热门
1China Annual Inflation 202650%概率
2Strait of Hormuz traffic returns to normal by December 31?19.6%概率
3Putin out as President of Russia by December 31, 2026?1%概率
四个榜
热门精选 = 策展 highlight 区；突发 = 策展 normal 区；高概率、今日热门 = 本地按当前列表计算（仅默认排序下有意义）
容器
一个 $surfaceVariant 底的区块，标题"榜单"，tab 行只列有数据的榜；只有一个榜时不显示 tab
行
单列最多 5 行：序号 · 标题（两行省略）· 右侧数值 + 单位徽标（概率 / 24h 成交 / 成交）
去重
进了精选的事件不进榜；一个事件只进优先级最高的榜：highlight › normal › 高概率 › 今日热门
为什么合并
原来四个榜两两并排，标题 9 个字就截断；榜单的核心信息就是标题，截断即失效
切换
tab 是渲染态，不发请求；切排序后本地两榜消失，tab 只剩运营位两项；一个都没有则整块隐藏
出口
"查看全部 ›" 仅在今日热门 tab 出现，进入 24h 成交排序的列表；其余榜没有等价全量视图，不放假出口

2.3 一屏内的重复控制

dev 数据只有十几个事件，同一件事很容易在精选、榜单、列表里出现三次。规则是：精选里的事件从榜单和列表里剔除；榜单之间互斥；列表不剔除榜单里的事件（榜单是排序视图，列表是全集，两者并存是合理的）。

03

分类与二级筛选

一级是 13 个轮播标签加固定的"全部"；二级来自 /tags/{id}/related-tags/tags，只在当前一级确实有子标签时渲染这一行。dev 上有二级的只有 Crypto（5M / 15M / 1h / 4h / Daily）、Weather（温度 / 降水 / 气象科学）、Iran（Oil）；Politics、Finance、Tech、Football 都没有，所以"没有二级"必须是常态，而不是一行空白。

A二级 chip 比一级弱一档：30 高、12/600、1dp 描边无底色；选中为 1.5dp 深描边 + 加粗，不反白。
B列表标题就是当前一级名，右侧总数来自分页返回的累计 + hasMore。
C空态卡是白卡 + 一句原因 + 两个文字链，与全 App 的空态一致。
04

视图、排序、收藏

"交易中 / 已结束 / 全部"是视图维度，"成交量 / 24h 成交 / 流动性 / 即将截止 / 最新"是排序维度，收藏是集合切换。三者从 chip 行里拿出来：两个下拉加一个开关，一行放完。

A`FilterSelect`：chip 显示当前值 + ▾；面板是 design-system `Sheet`，单选行 + 勾，选后关闭。
B`FilterBanner`：`$surfaceVariant` 底、10 号字、右侧文字链"清除"。
C收藏是集合不是筛选：本地逐个查询，搜索在集合内本地过滤。
05

搜索态

点击搜索框进入搜索态，筛选行收起，运营位隐藏。输入满 2 个字符、停顿 300ms 后请求平台 /public-search（已实测可用，返回事件、标签和分页信息）。结果分两段：标签段最多 5 个，点标签等于选中该分类并退出搜索态；事件段是标准卡片，翻页用 page。

A标签段用一级 chip 同款；事件段沿用列表卡，保持"搜到的就是列表里那张"。
06

更多分类

188 个标签里有 175 个不在轮播行。"更多 ▾"打开一个底部面板：顶部本地搜索，列表按首字分组（中文按拼音首字母），轮播里已有的标"常用"。选中后关闭面板，该标签以选中态插到一级行"更多"左侧，切回别的一级时移除。

07

空态与失败

分类下没有事件

空态卡："<分类> 暂无交易中的市场"，两个文字链：切到全部、看已结束。dev 上 Weather 就是这个状态。

二级接口失败

二级行不渲染，不阻塞列表；下拉刷新重试。

搜索接口失败

"搜索暂不可用 · 重试"文字链，不回退本地过滤。

分页失败

脚注"加载失败 · 重试"（已上线）。

标签全集失败

"更多 ▾"不渲染，其余照常。

运营位失败

精选 / 榜单整块不渲染，列表照常；现有 `predict-curation-error` 行保留为重试入口。

08

交互规则与状态参数

  1. 切一级：二级重置为"全部 <一级>"，视图 / 排序保留，列表滚回顶部拉第一页；运营位按出现条件收起或展开。
  2. 切二级：列表滚回顶部；一级保持选中；Crypto 的二级同时过滤周期系列卡（按 recurrence）。
  3. 改视图 / 排序：不滚顶（用户通常在看列表中段），原地刷新，出现"已筛选"提示行。
  4. 收藏开关：一级 / 二级 / 下拉置灰；关闭恢复之前的筛选。
  5. 下拉刷新：刷新当前筛选的第一页 + 运营位 + 二级标签。
  6. 返回：从详情返回保留筛选与滚动位置。

整页的状态就是下面这组参数。首页"查看全部 ›"、榜单"查看全部"、系列卡、通知深链都用它进入：

{ tag: string | null, // 一级或二级标签 id；null = 全部
  parentTag: string | null, // 选了二级时记一级，用于渲染二级行
  view: "trading" | "closed" | "all",
  sort: "volume" | "volume24h" | "liquidity" | "endingSoon" | "newest",
  q: string,
  favorites: boolean }
入口参数
首页"热门预测 · 查看全部 ›"{}（全部 · 交易中 · 成交量）
榜单"今日热门 · 查看全部 ›"{ sort: "volume24h" }
首页系列卡{ tag: "430", parentTag: "430" }（Crypto）
推送"新市场上线"{ sort: "newest" }

可行性与数据映射

2026-09-09 对 dev 平台 gamma-api.predict.prax1s.xyz 实测。方案需要的每一项平台都已具备；唯一的数据现实是二级标签稀疏、活跃事件少，这两点已在设计里当常态处理。

能力接口实测

标签全集GET /tags?limit=500&order=label&ascending=true可用 · 188 个，全部带 labelTranslation；无父子字段
二级标签GET /tags/{id}/related-tags/tags可用 · crypto 5 个 / weather 3 个 / iran 1 个；其余一级为空

服务端搜索GET /public-search?q&events_status&limit_per_type=20&page可用 · 返回 events / tags / pagination{hasMore,totalResults}
每标签事件数—平台未提供 · 面板里不显示数量，或后续由网关缓存统计
