# 链上充值提现的安全设计（2026-09-01）

范围：自托管钱包的链上转入（收款）与转出（转账），以及支撑它们的代币目录下发。
不含钱包 ↔ 预测账户的托管划转。

## 一、先认清信任根：服务端下发的配置

这套设计里，App 从服务端拿三样东西：**chainId、RPC 地址、代币合约地址**。它们都参与
资金操作，所以服务端（以及到服务端的链路）就是信任根。逐项看被篡改后的后果：

| 被篡改的值 | 后果 | 严重度 |
| --- | --- | --- |
| 代币合约地址 | 用户以为在转 USDT，实际转到攻击者的合约。确认页只显示"USDT"和金额，看不出区别 | **最高** |
| chainId | 用户在错误的链上签名，签名可在那条链上重放（EIP-155 的保护前提就是 chainId 正确） | 高 |
| RPC 地址 | 假余额、假回执、错误的 nonce | 中 |

结论：**不能把"服务端下发"当成"可信"**。下发解决的是"可配置"，不是"可信任"。凡是参与
资金操作的下发值，客户端都要有独立的断言。

### 已落地：chainId 断言

`applyDeliveredWalletConfig` 现在会丢掉 chainId 与协议事实不符的链，并留下 warning
（`wallet-runtime-config.ts`）。宁可少一条链，也不拿可疑的 chainId 去签名。

这里有个容易被后人误删的点，注释里写清了：客户端那份 `FALLBACK_CHAIN_IDS` 有**两个
角色**——服务端没下发时的兜底，以及安全断言。它不是"重复配置"。chainId 属于协议事实，
不属于租户配置；端点和 projectId 可以随租户变，chainId 不行。

### 已落地：确认页显示足以识别目标的信息

转账确认页原来只有缩短的收款地址（10+6）、链名、金额、手续费。现在补齐了三项：

- **完整收款地址**（带字间距便于逐字核对）+ 一句"转出无法撤销，请逐字核对"。
  缩略形式挡不住剪贴板劫持——伪造地址的首尾往往就是一致的。
- **代币合约地址**：合约地址被换掉时符号看起来完全一样，不显示它就等于没有防线。
  原生币显式写"原生代币（无合约）"，而不是把 `native` 这个哨兵值露给用户。
- **chainId 数字**：链名会重复（Base 和 Ethereum 的原生币都叫 ETH），chainId 不会。

另外用上了 `TokenRef.verified`：未验证代币的合约地址行变琥珀色，并展开一段警示说明
"地址被换掉时符号看起来是一样的"。**这一条对不会核对地址的普通用户是唯一有效的防线**。

### 待落地：主流代币地址白名单

对高价值代币（USDT / USDC 等）在客户端保留一份已知合约地址白名单，下发值不符就强制
降级为"未验证"走上面那条警示路径。现在 `verified` 完全来自服务端，服务端被攻破时它
也可以被设成 true。

### 硬规则：Multicall3 地址绝不下发

批量余额查询要用 Multicall3（`0xcA11bde05977b3631167028862bE2a173976CA11`，已实测在
bsc / eth / base / op-sepolia 上都是同一份部署）。它是所有余额读取的入口，被篡改可以
返回任意假余额。**必须硬编码在客户端**，不能进下发配置。

## 二、RPC 节点不可信

公共节点、租户自配的节点都可能返回任意数据。按影响分级：

- **假余额** → 显示错误，但**不影响签名安全**：签名内容是用户自己输入的金额和地址。
- **假回执** → 用户以为成功了。危害中等，缓解是始终提供区块浏览器链接让用户自查。
- **错误的 nonce** → 可能诱导重放。缓解：只从 `pending` 取；本地记住上次用过的 nonce
  并要求单调递增；同一地址串行发送（同时只允许一笔在途）。
- **虚高的 gas price** → 用户多付手续费。缓解：设一个绝对上限，超过就拒绝并提示，而不是
  照着签。

建议对 nonce 这类**参与签名**的读取做双节点交叉验证；余额这类只影响显示的不必要。

RPC 必须是 https（已有 `isHTTPSURL` 校验），且 URL 里绝不能带 bearer 密钥——下发给
所有客户端的东西按定义是公开的（服务端代码里已有这条注释）。

## 三、交易构造：两个已实测的陷阱

**1. ethers 缺字段不报错。** 只给 `chainId/to/value`、不给 `nonce` 和 `gasLimit`，
`Wallet.signTransaction` 照样签得出来，用的是默认值（nonce=0、gasLimit=0）。这比报错
危险：**nonce=0 可能重放一笔很久以前的交易**。

所以签名前必须有显式的字段完整性校验（nonce / gasLimit / 费用 / chainId 全部存在且
合理），不能指望 ethers 拦。这是必须写单测的地方。

**2. `eth_estimateGas` 在余额不足时 revert**，报文形如
`execution reverted: BEP20: transfer amount exceeds balance`。它含合约内部信息，
不能直接显示给用户，要映射成 `Tx.reasonKey`。顺序必须是：先查余额自己比较 → 给人话
提示 → 余额够了才估 gas。

另外 gas 估算值会随收款方状态浮动（实测同一笔 USDT 转账，收款地址已有余额时 34,646，
从零变非零时 29,838），所以 buffer 必要，估算值不是精确值。

## 四、私钥：既有边界与无法解决的限制

现有 `KeystoreVault` 做对的部分：AES-256-GCM 加密、包裹密钥放 SecureStore
（Android Keystore / iOS Keychain）、生物识别解锁、私钥只在 `withPrivateKey` 的回调
作用域内存在且不作为返回值离开、助记词界面有 FLAG_SECURE。

**无法解决的**：JS 字符串不可变，私钥在内存里**没法擦除**。只能缩短生命周期。用
`Uint8Array` 承载并 `fill(0)` 理论上可行，但 ethers 的 `Wallet` 需要 hex string，
中间还是会产生不可擦除的副本，收益有限。这一条应当如实记录，而不是假装解决了。

## 五、转出（提现）的防误操作

- **剪贴板劫持**：恶意应用可以替换剪贴板里的地址。粘贴后必须显示完整地址并要求确认。
- **目标是合约地址**：`eth_getCode` 非空时警示——往不支持提取的合约转代币会永久锁死。
- **首次转给新地址**：走已有的 `requireVerification`（按金额触发生物识别）。
- **有代币没 gas**：必须在输入金额时就提示，而不是签名后失败。
- **「全部转出」必须扣掉 gas**，否则必然失败。

## 六、日志与遥测

绝不能出现在任何日志、遥测、崩溃报告里：**私钥、助记词、包裹密钥、签名后的 raw tx**。

地址和 txHash 是链上公开信息，但**把它们和用户身份或设备 ID 关联上报会泄露隐私**——
链上地址一旦和一个人对应，他的全部历史交易就都公开了。遥测里只上报聚合指标，不上报地址。

## 七、服务端侧（代币目录）

- 从链上读代币元数据时，RPC 调用要有**超时和响应大小上限**：恶意或故障的节点可以返回
  巨大响应打满内存。
- 合约地址入库前做 EIP-55 校验并**规范化大小写**，否则同一地址的不同写法会绕过唯一键
  产生重复条目。
- 管理端对合约地址的写入走既有审计（reason + 乐观锁 + audit_events）。

## 八、测试链的隔离

OP Sepolia 已加入平台目录，并带 `testnet` 标记贯穿到管理端与 App。两条相关的安全考虑：

- **默认不启用**：没配过钱包段的租户不会自动拿到测试链（`normalizeWallet` 里跳过
  testnet）。否则新增一条测试链就会静默出现在所有租户里。
- **界面必须区分**：测试链代币没有价值，和主网并排出现时用户会当成真资产。管理端已加
  「测试网」徽标和启用时的警示；App 侧显示测试链资产时同样需要视觉区分（待做）。

## 九、进展与剩余优先级

### 已完成

- **chainId 断言**：下发值与协议事实不符的链会被丢弃（`wallet-runtime-config.ts`）。
- **签名前字段完整性校验**：`transaction-guard.ts`。`assertLocallySignable` 要求
  nonce / gasLimit / 两个费用字段齐备，拒绝 priority > max，并设了 10000 Gwei 的手续费
  绝对红线。13 个用例覆盖，其中"缺 nonce 必须报错"是核心——ethers 不报错。
- **`assertSubmittable`** 里的 EIP-55 校验，同时接受交易所常给的全小写地址、拒绝
  混合大小写但校验和错误的地址（那通常是手抄错了一个字符）。
- **signer 抽象修正**：`signTransaction` → `submitTransaction`，返回 txHash。
  外部钱包走 `eth_sendTransaction`（MetaMask 不支持 `eth_signTransaction`），
  内置钱包本地签名后调用注入的 `broadcast`。签名器仍然不碰网络。
- **确认页显示完整收款地址、代币合约地址、chainId，以及未验证代币的警示**
  （`send-screen.tsx`，4 个用例覆盖）。
- **配对请求不再要求 `eth_signTransaction`**：它在 `requiredNamespaces` 里意味着
  "钱包必须支持"，声明一个 MetaMask 没有的方法可能被拒绝配对。改用
  `optionalNamespaces` 并去掉该方法。

### 已落地（链层）

`core/chain/` 下的两层，各自有测试（RPC 客户端 9 例、链客户端 14 例）：

- **`rpc-client`**：超时用 `AbortController` 真的取消请求（不是只放弃等待，否则移动
  网络下会攒下一堆没人等的连接）；多端点按顺序回退；**合约 revert 这类执行错误不重试**
  （换个节点结果一样）；节点原文留在 `detail` 里而不是塞进给用户看的 message；
  没有端点时明确失败，不猜一个公共节点。
- **`chain-client`**：
  - **nonce 单调性**：取 `pending` 并叠一层本地下限，节点报一个更小的值时不采纳
    （那会让用户签出重放旧交易的签名）。按地址分别记。
  - **相对手续费上限**：超过节点报的 `gasPrice` 四倍就拒绝。虚高的费用会把用户的
    原生币烧成手续费。同时以 `gasPrice` 为下限——报得太低会让交易永久 pending。
  - 费用公式 `baseFee × 2 + tip` 对四条链都成立（BSC 的 baseFee 恒为 0，自然退化）；
    节点不支持 `eth_maxPriorityFeePerGas` 时退回 `gasPrice`。
  - **Multicall3 地址硬编码在这里**，不接受任何下发值。
  - gas 估算加 20% buffer；单条代币查询失败不影响整批。
  - 回执区分「链上 revert」和「还没上链」——前者钱花了 gas 但没成功。

### 已落地（转账编排与代币白名单）

**`core/chain/transfer-service`**（15 例）把前面的零件串成一条链：预检 → 构造 →
校验 → 签名提交 → nonce 记账。

- **同地址串行**：每个地址一条队列，同时只允许一笔在途。并发会读到同一个 nonce，
  后一笔要么替换前一笔、要么永久 pending。前一笔失败不堵住后一笔。
- **余额自己比**，不把节点的 revert 报文丢给用户。`InsufficientGasError` 与
  `InsufficientBalanceError` 是两个类型——"我有 USDT 为什么转不了"是这类 App 最高频
  的困惑，UI 必须能分开讲。
- **nonce 只在广播成功后占用**，失败留给下一笔重用，不留空洞卡住后续所有交易。
- `estimateFee` 与 `maxNativeAmount` 让 UI 能在用户签名前就提示手续费，且"全部转出"
  会扣掉手续费——不扣就是必然失败，而用户只会反复重试。
- 手续费只为本地签名准备：signer 现在声明 `managesOwnFees`，外部钱包自己算 nonce
  和 gas，替它准备既浪费三次 RPC 也可能冲突。

**`core/wallet/config/token-allowlist`**（9 例）：`verified` 只能由客户端这份表授予，
**下发的 verified 值一律不采纳**——服务端被攻破时它可以把攻击者的合约标成已验证。

表里同时存 symbol 与 decimals，因为 decimals 错会让金额差 10ⁿ 倍。三种判定：
`verified`（对得上）、`unlisted`（租户自定义代币，按未验证展示）、`mismatch`
（在表里但元数据不符——这是配置错误或篡改，**应当拒绝这个代币**而不是降级展示）。

表里的地址全部经链上核验，其中一条值得记住：**同一个 USDT，BSC 上 18 位精度、
以太坊上 6 位**。凭直觉填必然出错。测试链不给任何背书。

### 已落地（转出走真链）

`features/wallet/api/onchain-transfers.ts` 把链层接进了网关。**可用性就是开关**：
一条链只有在服务端下发了 RPC 端点时才走真链，否则回落 Mock 账本——不需要额外的
feature flag，灰度等于"给哪个租户配 RPC"，也绝不猜端点。

走真链之后才成立的几件事一并补齐：

- **手续费不再写死**。之前是 `≈ 0.0003 BNB` 的常量，现在走 `eth_estimateGas` +
  费用数据，拿不到就显示"暂不可估"。编一个数字更糟：写小了用户会以为余额够。
  预估固定用 1 wei 询链——`estimateGas` 在余额不足时 revert，照用户输入估算会在
  用户边输入边报错。
- **原生币"全部转出"扣掉手续费**，不扣就是必然失败而用户会反复重试。
- **失败原因分开讲**（`features/wallet/model/transfer-errors.ts`，8 例）：缺 gas /
  余额不足 / 连不上节点 / 节点拒绝 / 用户取消 / 验证失败 / 钱包无响应 / 字段被守卫
  拦下 / 代币元数据不符，各自一条文案。节点原文（合约内部话）只进日志。
- **链上转账合并进历史列表**。Mock 账本不认识真链上的交易，不合并的话用户转完账
  回列表会以为这笔没发生。只在内存里——完整链上历史需要索引服务。
- **回执轮询按状态放慢**：进入等待出块阶段后 2.5s 一次，真链出块要几秒，800ms
  一次只是在撞节点限流。

**代币白名单接进了路径**。之前它有 9 个用例但没有任何调用方——看起来有防线，实际
不在路径上。现在 `getBalances` 统一过一遍 `trustedTokens`：下发的 `verified` 一律
不采纳、只有客户端那份表能授予；元数据不符的代币**直接丢掉**（decimals 错会让显示
金额差 10ⁿ 倍，显示一个错的数字比不显示更危险），并留 warning。`send` 里再挡一次。

**RPC 端点的 https 断言（客户端第三层）**。服务端已经校验并过滤两遍，客户端再滤一遍，
理由和 chainId 断言一样："必须是 https" 是客户端自己就能判断的协议事实。明文 RPC 的
后果不只是泄露用户查询的每个地址和余额——中间人还能返回伪造的余额和回执，让界面显示
一笔从未发生的转账已确认。

**地址簿的示例地址删掉了**。CRUD 是已知缺口，之前放着「交易所 A」「冷钱包」两条编出来
的地址；转出走真链之后，点一下就是把真钱发给一个谁都不拥有的地址，而转出无法撤销。

### 全面审计后的加固（2026-09-02）

四路对抗性审计（安全 / 正确性与并发 / 体验 / 服务端与管理端）之后落地的，按资金风险排序：

**一个前提被证伪：「下发端点 = 灰度开关」不成立。** 服务端对没配过端点的租户也会
下发平台默认 RPC（线上 anyfun 三条主网都有），所以"有端点"不是开关，是常开。现在真链
转出要同时满足：租户在管理端显式打开 `wallet.onchainSends`（默认关，非布尔拒绝），
且该链有 https 端点。老服务端不下发该字段时按关处理。线上已确认下发 `false`。

**签名的手续费必须是用户看到的那个数。** 报价与签名是两次独立询链，恶意节点可以
报价时报低、签名时报高；四倍相对上限对恶意节点无效（基准也是它报的）。现在确认页
把看到的手续费带进 `SendRequest.maxFee`，签名前实际费用超出四分之一就拒绝并要求
重新确认；真链上没有报价就不能提交。绝对红线改为按链：eth 2000 / bsc 200 /
base、op-sepolia 100 Gwei（历史极端拥堵的几倍），恶意节点能造成的损失有界。

**一笔不能变两笔。** 三条双发路径：确认按钮在等待生物验证期间可再点（守卫握到
mutation 结束）；广播超时换节点重发被判失败诱导重试（结果不明时问节点认不认识本地
算出的 hash）；余额预检在估 gas 之后导致真链上永远看不到"余额不足"这句人话（顺序
调换）。

**节点是不可信的，逐项补齐：** txHash 本地从签名原文算出、不信节点回答；回执必须属于
这一笔（transactionHash 对不上当没查到）；QUANTITY 统一解析（`0x`、空串、十进制归一成
RpcError）；pending 与 latest 的 nonce 差距超过 32 拒绝，本地下限只由真正用掉的 nonce
抬高且十分钟过期；单笔转账 gas 上限 500k（恶意代币可以把 transfer 写成烧光全部 gas）；
节点不支持 `eth_maxPriorityFeePerGas` 时小费不再整个用 gasPrice。

**收款地址的两道输入期防线：** 大小写混合但校验和不对（几乎总是抄错一个字符）单独
叫出来，而不是显示绿色"校验通过"再在签名前被 ethers 拦；收款地址是代币合约本身
（永久丢失）直接拦。确认页金额改为签名的精确值（`formatMoney` 会把 1.009 显示成 1.01）。

**余额与转出的一致性：** 开了链上转出的链，原生币余额来自真链（代币仍要等目录）；
进度页固定在提交那一刻的数据上，余额刷新不会让它换币或卸载；提交记录作为轮询的
initialData，某次轮询失败不会退回"还没签名"。

**服务端与管理端：** URL 校验改用真正的解析器（之前 `https://not a url`、
`https:///`、带账号密码的地址都能通过，而 App 会拒绝整份 bootstrap）；全是未知链时
回退主网默认而不是下发空列表；配置中心不再把归一化后的 wallet 段 PATCH 回去（会把
平台默认端点固化成租户快照）；409 之后刷新；配置对象改宽松模式，未知字段透传；
"强制升级"对商店 / MDM 渠道也生效；updatePolicy 的版本号必须是 semver。

### 链开关落地到 App 界面（2026-09-02）

代币目录落地后再对照"链和币种都有开关"复核，发现**链开关只走到了 WalletConnect
客户端**：管理端勾掉一条链、服务端确实不再下发它的 networks，但 App 里所有列链的地方
（余额汇总、转出页链选择器、账户详情与收款页的链列表）仍遍历写死的 `CHAINS`。关掉的
链没有端点，于是落到演示账本——以线上租户（只开 eth 与 op-sepolia、`onchainSends`
已开）为例，资产页会把 eth 的真余额和 BSC、Base 的演示余额并排显示，用户还能在 BSC 上
做一笔"演示转出"。没有资金风险（演示链不签真交易），但"关掉"变成了"变成假的"。

现在 `enabledChains()` 是界面上"有哪些链"的唯一来源（下发 networks 的 id 集合，经过
chainId 断言；老服务端不下发时回落三条主网）：

- 余额汇总只查、只显示启用的链；按链查询一条关掉的链直接返回空；
- 转出页与账户详情只列启用的链，入口带来的链若已被关掉，落到第一条启用的链；
- 内置钱包账户的"支持的链"直接取租户启用的链（一把 EVM 私钥在每条链上都能用，注册表
  里存的那份只是创建时的快照）；外部钱包取会话批准的链与启用链的交集；
- 收款页：可选链 = 账户支持的链 ∩ 启用的链（对不上时退到启用的链）；"支持的币种"改读
  下发的代币目录，老服务端没下发时只提原生币；测试链在 chip 上打标并单独提示，避免把
  主网资产打到测试链地址（EVM 同地址，资产不丢但在错的链上）。

DEX 模块三个页面的链筛选仍遍历 `CHAINS`：那几页目前全是演示数据，等 DEX 接真实数据时
一并改。
