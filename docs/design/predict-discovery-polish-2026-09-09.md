# 预测市场：精选 / 推荐位 / 周期市场操作 UI 与交互优化

日期：2026-09-09 · 状态：设计稿，待确认 §7 · 范围：RN-App（`market-list-screen.tsx`、`series-screen.tsx`、`series-period-card.tsx`、`series-period-rail.tsx`、`series-card.tsx`、design-system）

## 1. 现状与问题（模拟器 rn_smoke，1.2.11 + OTA rev 2，Politics / Crypto 标签实拍）

### 1.1 精选轮播（hero）

| 现状 | 问题 |
| --- | --- |
| 普通 `HorizontalScroll`，卡宽 300，无吸附、无页点 | 第二张只露一条边，滑到中途停在两张之间，第一张被截成一条黄色竖条；用户感知不到"这是可以横滑的一组" |
| 卡 = 大图 110 + 标签 + 两行标题 + 最多 3 行结果（每行 百分比 + Yes/No 两键）+ 统计，约 620 px | 一张卡占满首屏可视区，筛选条以下所有内容被顶到二屏；多结果事件与单结果事件高度差一倍，相邻两张一高一矮 |
| 黄底（primary 26% 透明）大面积铺色；图片 276×110 硬裁 | 与页面其它白卡不一致，人像被截头 |
| 首页"热门预测"已改为 `SnapCarousel`（peek + 页点） | 同一 App 两套横滑手感 |

### 1.2 推荐位（热门精选 / 突发 / 高概率 / 今日热门）

| 现状 | 问题 |
| --- | --- |
| 两个榜单并排，各占半屏 | 标题只剩约 9 个汉字就截断（"China Annual Inflation 2…"），榜单的核心信息是标题，截断即失效 |
| 四个榜与精选来自同一批事件 | 通胀 / Fed / China Inflation 三个事件在精选、热门精选、突发、高概率里各出现一次，前两屏全是重复 |
| 右列数值混用概率（14%）、成交额（$89.7）、"—" | 同一列三种含义，无单位提示 |
| 精选与榜单没有区块标题，只有周期市场有 | 用户分不清哪里是运营位、哪里是列表结果；切排序时榜单消失（只在默认排序出现）也没有解释 |

### 1.3 周期市场（Crypto 标签 → 系列卡 → 系列页）

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| 系列卡（列表） | 无报价时仍渲染 `Yes —` / `No —` 两个大按钮，左侧一个孤零零的 "—" | 像坏掉的界面；无报价本来就不该给"可点"的观感 |
| 系列卡 1h | "暂无窗口"一行灰字 | 没有说明原因或下一步，和其它两张卡形态不一致 |
| 期卡底部 | `查看详情` 是一颗 32 高的灰色 SecondaryButton，贴在卡左下角，和上面两颗满宽的 涨 / 跌 主按钮平级出现 | 低频动作（持有人、成交明细）被做成了"第三个按钮"，视觉权重错位；单独一颗小灰按钮孤立在左下，右侧留白 |
| 期卡右上 | `回到当期` 也是灰 SecondaryButton；不是当期时与 `下一期已开始 · 去看` 一起最多出现三颗灰按钮 | 同一张卡上三种灰按钮，层级全部拉平 |
| 期轨道 | `更早 ▾` / `更多 ▾` 与期芯片同色同高 | 动作和数据混在一排，看起来像两个叫"更早""更多"的期 |
| 历史窗口 | 12 行后一颗满宽灰色 `加载更早` 大按钮；"更早"抽屉底部同样 | 分页动作做成页面级主按钮，比下单按钮还大；每行重复 "9/9 ·" 日期前缀 |

## 2. 目标与原则

1. **运营位是"看"，列表是"选"**：精选、榜单要一眼读完，不承担下单；下单只留在卡片详情与周期市场期卡。
2. **一个页面一套横滑手感**：所有横向卡组统一 `SnapCarousel`（吸附 + peek + 页点）。
3. **按钮层级只有三档**：主（涨 / 跌 / 买 Yes / 买 No，满宽实心）、次（回到当期 / 重试，描边小胶囊，最多一颗）、三（详情、更早、更多、加载更早，文字链或图标，不占块）。
4. **分页不做成按钮**：列表到底自动加载，脚注文字说明状态；只有失败才出现"重试"。
5. **不重复**：同一事件在首屏运营位只出现一次。
6. **有标题、有出口**：每个运营区块有标题与"查看全部 ›"。

## 3. 精选（hero）设计

- 组件：`SnapCarousel`，`fullWidth` + `peek=24` + `showDots`（≥2 张时）；1 张时不用轮播，直接单卡满宽。
- 卡片固定高度（约 300 px）："海报式"：
  - 图片全宽、16:9、圆角 12，`resizeMode=cover`；图上左上角"✦ 精选 · 分类"角标（半透明黑底白字），右上角收藏星。
  - 标题两行（`SectionTitle`，超出省略）。
  - 一行结果摘要：首个结果的名称 + 概率（如 "Above 4.5%  14%"），右侧一对 compact `Yes 14¢ / No 86¢`；多结果时下方灰字"共 5 个结果 · 成交 $89.7"，点卡进详情看全部。
  - 卡底白色（`$surface`），细描边，去掉黄底。
- 区块标题："精选" + 右侧"查看全部 ›"（进入 discovery 全量列表，或收进"全部"筛选）。
- 交互：整卡可点进详情；Yes/No 直接开下单面板（沿用 `onOrder`）。

## 4. 推荐位设计

- 四个榜合并为一个区块 **"榜单"**，顶部一排 tab 芯片：热门精选｜突发｜高概率｜今日热门（只显示有数据的 tab，默认第一个）。
- 榜单单列，最多 5 行：序号 · 标题（完整，两行省略）· 右侧数值 + 单位徽标（`概率` / `24h 成交` / `成交`），无数据显示"—"并灰化。
- 去重：进入精选的事件不进榜单；榜单之间同一事件只出现在优先级最高的榜（运营位 highlight > normal > 本地 高概率 > 今日热门）。
- 排序切换时（非默认排序），本地两榜不出现，tab 只剩运营位两项；一个都没有时整个区块隐藏，不留空标题。
- 区块右上"查看全部 ›" 进入当前 tab 的完整榜（复用列表页筛选：高概率 = 按概率排序，今日热门 = 24h 成交排序）。

## 5. 周期市场操作设计

### 5.1 系列卡（列表）

- 有报价：保持 `涨 xx¢ / 跌 xx¢` 两键。
- 无报价：不渲染两键，改一行灰字"暂无报价 · 点击查看走势"；整卡可点进系列页（已有）。
- 1h 无窗口："暂无窗口 · 平台尚未生成下一期"，卡右侧显示周期徽标即可。

### 5.2 期卡按钮层级

```
[进行中  06:10 – 06:15]                      [回到当期]   ← 仅非当期时，一颗次级胶囊
剩余 00:01:11
参考价 …    当前价 …   较参考价 …
[    涨 · 52¢    ] [    跌 · 48¢    ]                     ← 主按钮不变
暂无挂单，市价单可能无法成交                              ← 提示行不变
────────────────────────────────────────────
本期详情 · 持有人 / 成交明细                         ›    ← 卡底"链接行"，48 高，整行可点
```

- `查看详情` 灰按钮删除，改为卡底链接行（`LinkRow`：左文案 + 右 chevron，无边框、无底色、上方 1 px 分隔线）。
- `下一期已开始 · 去看` 从灰按钮改为卡内顶部一条浅色横幅（`$surfaceVariant` 底，左文案，右"去看 ›"），只在"停在有仓位的已结束期"时出现，与"回到当期"不同时出现（有横幅就不显示回到当期）。
- 卡上最多同时存在：两颗主按钮 + 一颗次级胶囊 + 一行链接。

### 5.3 期轨道

- `更早 ▾` / `更多 ▾` 改为轨道两端的圆形图标按钮（‹ / ›，36×36，`$surfaceVariant` 底，与 44 高的芯片错开），不再与期芯片同形；长按或点开仍是现有抽屉。
- 轨道左侧固定"更早"图标（不随滚动移出），右侧"更多"仅在有更多未来期时出现。

### 5.4 历史窗口分页

- 页面底部与"更早"抽屉都改为 **到底自动加载**：`onEndReached`（阈值 0.6）触发 `fetchNextPage`；底部一行 32 高脚注：
  - 加载中："正在加载更早…"（带小 spinner）
  - 还有更多但未触发："上滑查看更早"（灰字）
  - 没有更多："已显示全部 N 期"
  - 失败："加载失败 · 重试"（文字链，只有这里保留可点）
- 历史行：按日期分组，组头一行 "9 月 9 日"，行内去掉 "9/9 ·" 前缀；行右侧结果"涨 / 跌"下加一行小字变动额（结算 − 参考，带正负号与颜色）。
- 默认仍取最近 12 期（一页），滚动到底再翻。

### 5.5 全局"三级按钮"落到 design-system

- 新增 `LinkRow`（链接行）与 `TextLink`（行内文字链）两个组件；`SecondaryButton` 只保留给"次级动作"。
- 后续其它页面的 "查看全部 / 更多 / 展开" 统一走这两个组件。
