## 2. 与设计一致（抽查记录）

- 验证策略：`smart` 的窗口由 `authenticate()` 成功即记录，金库端口 `expoAuthenticate` 走同一函数，所以签名验证也计入"最近验证过"；`always` 先 `lockKeys()` 再放行（`use-require-verification.ts`）。应用上锁 `forgetVerification()`（`useAppLock.lock`）。
- 启用流程：`useEnablePredict.done` 随 `onStep` 推进；`approvalsVerified` 先看凭证里的 `approvedSafe` 再读链，`enable()` 等到授权可见后写入。
- 资产：`composeOverview` 逐链；`wallet.chains` 只数这次拿到余额的链；未定价持仓与未返回的链都算"部分合计"，但 `loading` 期间不显示"部分合计"文案（避免每次打开都闪一下警告）。
- 盘口：`deriveBookView` 的 No 侧镜像、累计额、卖盘远→近排列均与网页版 `OutcomeOrderbook` 一致（单测 4 例）。
- 记录：平台索引到的取回以平台为准（`mergeFundRecords`），本机记录只补索引没追上的。
- 退出：首页两次返回（边缘滑动 / 返回键）2 秒窗口；iOS 不做。交互规范 §1 原文"首页再按走系统"被本需求覆盖。
- 平台契约 §3.7 各条（429 退避、40101 重签、CLOB 401 丢密钥、重装清凭证、SafeTx 串行、限流不重试）本轮未触碰，仍成立。

## 4. 遗留问题与设计方案

### 4.1 链上收款记录（设计 §3.3）

**现状**：App 只能列本机发出的转出；打到地址上的转账没有来源。`eth_getLogs` 在公共节点上有区块范围与速率限制，客户端扫链不可行。

**方案（RN-Server）**：

1. 新表 `wallet_transfer_index`：`tenant_id, chain, address, direction(in|out), token_address, amount_raw, counterparty, tx_hash, log_index, block_number, block_time`，唯一键 `(chain, tx_hash, log_index)`；索引 `(tenant_id, address, chain, block_number desc)`。
2. 索引器：每条启用的链一个 worker，用平台端点按区块窗口拉 `Transfer(address,address,uint256)` 日志（topic1 / topic2 = 已登记地址），原生币入账用 `eth_getBlockByNumber(full=true)` 过滤 `to`；地址来源是 `wallet_user`（SIWE 登录过的地址）。游标表 `wallet_index_cursor(chain, block_number)`；回退 12 个块处理重组。
3. 接口 `GET /v1/mobile/wallet/transfers?address=&chain=&cursor=`（与现有 bootstrap 同一鉴权 / 租户头），返回上表字段 + 目录里的代币元数据。
4. App：`WalletGateway.listTransfers` 改为 本机转出账本 ∪ 服务端索引（按 `tx_hash` 去重，服务端为准），记录页"钱包转账"Tab 去掉"需要索引"的说明；收款页在收到入账时推送提醒（复用现有推送链路）。
5. 门禁：索引器只处理租户 `wallet.networks` 启用且 `onchainSends=true` 的链；索引落后时接口带 `indexedUpTo`，App 显示"已索引到 N 分钟前"。

### 4.2 主网 `unwrapDelay` 2 小时的"可领取"提醒（平台文档 §5.4）

**方案**：发起取回成功后，App 用 `expo-notifications` 排一个本地通知（`claimableAt`），点击深链 `anyfun://records?tab=predict`；同时把 `requestId + claimableAt` 交给 RN-Server（`POST /v1/mobile/reminders`）作为服务端推送的后备（设备关机 / 本地通知被清）。两条都是"事实驱动"的时间点，不猜延迟。

### 4.3 争议提交（平台无入口）

`submitDispute` 仍抛 `PredictUnsupportedError`；结算页把按钮换成"平台暂不支持"的只读说明，避免用户以为是 App 坏了。**需要平台侧开接口**（gamma `POST /markets/{id}/dispute` 或链上 adjudicator），App 侧的签名与押金流程按平台契约再定。

### 4.4 领取（redeem）未在真实结算市场验证

dev 上没有会结算的市场。方案：请平台在 prax1s 建一个 5 分钟到期、自动结算的测试市场（`recurring` 系列即可），验证 `redeemPositions` 的 MultiSend 与 `/positions` 的 `redeemable` 判定后再开放主网领取入口。

### 4.5 iOS 未验证

无 macOS 构建环境。至少要在 EAS 上出一次 iOS dev build 验：锁屏面容图标、`GestureDetector` 与原生 stack 手势的共存（二级页边缘返回由 native-stack 处理，AppShell 的边缘手势只在标签页）、`BackHandler.exitApp` 分支已按平台跳过。

### 4.6 偏好存储小清理

`appLockMethod` 字段无读取方；`largeAmountThresholdUsd` / `autoLockMinutes` 用"点一下循环切换"的交互（安全中心 `cycleLock` / `cycleThreshold`）不符合交互规范 §2 的"选择器"要求。方案：偏好存储升 v3 删除 `appLockMethod`；两个数值改为 `RadioRow` 面板（复用 `TxVerificationSheet` 的形态）。

### 4.7 多结果事件的多线走势

已实现（`usePriceHistories` + 图例），模拟器上对 dev 的"inflation"多结果事件核过一次；线的颜色取自主题 token（涨跌色 / info / warning / muted），超过 4 条只画概率最高的 4 条，与网页版 `MAX_VISIBLE_HISTORY_LINES` 相同。
