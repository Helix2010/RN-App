# 滚动折叠导航（大标题 → 紧凑标题）交互设计

日期：2026-09-09 · 状态：已确认（§7 四项全做）并实现，变更记录 `docs/changes/2026-09-09-feat-collapsing-header.md` · 范围：RN-App 设计系统 + 事件详情 / 系列页 / 代币详情 / 预测列表 / DEX 行情 / 首页 / 资产页

## 1. 问题

事件详情页顶部是固定的一行导航（返回 · 分类 · 收藏 · 状态徽章），事件图标与标题在滚动内容里。往下看走势 / 盘口 / 规则时
标题一滚就没了，用户不知道自己在看哪个市场；导航栏上只剩"POLITICS"这种分类，信息量最低的一行反而常驻。

用户提出：上滑时标题与图片吸顶并缩小，导航栏一并变化；滑回顶部时恢复。本文给出具体交互规格，并分析其它页面是否也适用。

## 2. 交互规格（事件详情页）

### 2.1 两个稳定态

```
展开态（scrollY = 0）                         折叠态（scrollY ≥ 阈值）
┌──────────────────────────────────┐          ┌──────────────────────────────────┐
│ ‹   POLITICS          ☆  [交易中] │ 导航 44  │ ‹  ▣ Will BTC hit 120k b…  ☆ [交易中]│ 导航 44
├──────────────────────────────────┤          ├──────────────────────────────────┤ ← 细线淡入
│ ▣▣  Will BTC hit 120k before      │          │ （走势图 / 市场 / 盘口……）           │
│ ▣▣  October?                      │ 英雄区   │                                  │
│ 12 天后截止 · Vol $1.2M           │          │                                  │
│ 24h $80K · 流动性 $300K           │          │                                  │
│ #politics #crypto                 │          │                                  │
│ ─────── 走势图 ───────            │          │                                  │
```

- **展开态**：导航行 = 返回 + 分类小字（eyebrow）+ 收藏 + 状态徽章；英雄区（图标 48 + 标题 20/700 最多 3 行 + 截止 / 成交量 + 标签）随内容滚动。
- **折叠态**：导航行中间换成 **紧凑标题**：图标 22（圆角 6）+ 标题 15/600 单行尾部省略；分类小字消失；导航底部 1px 细线出现，
  与下方内容分层。返回、收藏、状态徽章位置不变——用户手指已经记住它们在哪。
- 底部固定的 Yes / No 下单栏不参与，保持现状。

### 2.2 过渡：由滚动位置驱动的插值，不是状态切换

```
阈值 T = 英雄区标题块底边相对导航底边的距离（onLayout 测得，随标题行数变化）
scrollY ∈ [T − 24, T]    展开态中间（分类小字 / 大标题）opacity 1 → 0；紧凑标题 opacity 0 → 1，translateY 8 → 0
scrollY ∈ [T − 8,  T]    导航底部细线 opacity 0 → 1
全部 clamp；无弹簧、无时长，手指停在哪里画面就停在哪里
（实现时把分类小字的淡出与紧凑标题的淡入合成同一段交叉：两段分开时中间会有一段导航空着）
```

- **为什么是"交叉淡入"而不是把大标题真的缩小吸顶**：
  1. 大标题可能两三行，缩小后无法变成单行，必然要换一个单行版本，等于还是两个标题。
  2. 对文字做 `scale` 变换在 Android 上会发虚；改 `fontSize` 触发布局，必须走 JS 线程，滚动时会掉帧。
  3. iOS 大标题（Large Title）与 Material 的 collapsing toolbar 都是同一做法：大标题随内容滚走，紧凑标题在导航里淡入，视觉上就是"缩小上去了"。
- **恢复**：插值是双向的，滑回顶部自然回到展开态，没有单独的"恢复"逻辑，也不会出现来回抖动。
- **图标**：紧凑标题带 22px 图标，英雄区 48px 图标随内容滚走。没有图标的事件（平台 `icon` 为空）紧凑标题只显示文字，不占位。

### 2.3 细节与边界

| 项 | 规格 |
| --- | --- |
| 导航高度 | 44 + 状态栏；折叠前后不变，内容不会因折叠跳动 |
| 紧凑标题可点 | 点一下滚回顶部（`scrollTo({ y: 0 })`），与 iOS 状态栏点击回顶同一心智 |
| 无障碍 | 英雄区标题是页面的 heading；紧凑标题 `accessible={false}` + `importantForAccessibility="no-hide-descendants"`，读屏不会念两遍 |
| 走势图刻度手势 | 现有 `scrollEnabled={!scrubbing}` 不变；刻度时滚动停住，折叠状态也停住 |
| 数据未到 | 英雄区骨架时阈值按骨架高度算；数据到了 onLayout 重新测，插值区间随之更新 |
| 标题极长 | 英雄区最多 3 行（`numberOfLines={3}`），紧凑标题 1 行尾部省略；无障碍标签用全文 |
| 减少动态效果 | 系统开了"减少动画"时插值仍按滚动驱动（这不是自动播放的动画），不需要特判 |
| 性能 | `Animated.ScrollView` + `useAnimatedScrollHandler` + `useAnimatedStyle`，全部在 UI 线程（worklet），与 `SnapCarousel` 同一套；不经过 JS 桥 |

## 3. 设计系统落点

新增一个组件而不是在详情页里手写，让 §4 里其它页面复用同一套时序与尺寸：

```tsx
<CollapsingHeader
  onBack={onBack}
  backLabel={t("action.back")}
  eyebrow="POLITICS"                       // 展开态导航中间；可空
  compact={{ icon: iconUrl, title }}       // 折叠态导航中间（§4 的 status 变体传 subtitle 行）
  actions={<Row>…收藏、状态徽章…</Row>}
  hero={<Stack>…图标 48 + 标题 + 截止 / 成交量 + 标签…</Stack>}   // 阈值按它的高度测
  scrollEnabled={!scrubbing}
  paddingBottom={120}
>
  {children}
</CollapsingHeader>
```

- 内部：`Animated.ScrollView`（替代 `PageScroll`，保留 `refresh` / `keyboardShouldPersistTaps` / `scrollRef` 三个已有属性）；
  `scrollY` 共享值；英雄区 `onLayout` 得到阈值；三段插值见 §2.2。
- 与 `ScreenHeader` 的关系：`ScreenHeader` 保留给标题固定的页面（设置、划转、排行榜……）；`CollapsingHeader` 只给"英雄区会滚走"的页面。
- 测试：插值函数 `headerProgress(scrollY, threshold)` 纯函数单测；组件在 jest 的 reanimated 替身下按静态首值渲染（紧凑标题 opacity 0），
  现有详情页用例按文字找标题不受影响；紧凑标题只在 `accessibilityElementsHidden` 下存在，用 `includeHiddenElements` 断言。

## 4. 其它页面分析

按"滚走的是什么、滚下去之后用户最需要看见什么"逐页看，分三类。

### 4.1 适用同一交互（标题折叠）

| 页面 | 现状 | 折叠后导航中间显示 | 说明 |
| --- | --- | --- | --- |
| **事件详情**（预测） | 导航只有分类；标题 + 图标在内容里 | 图标 + 标题 | 本文主体 |

### 4.2 适用"状态折叠"变体（标题本来就在导航里，滚走的是状态 / 价格）

| 页面 | 现状 | 折叠后导航副标题换成 | 说明 |
| --- | --- | --- | --- |
| **周期市场系列页** | 导航已是系列名；滚走的是期轨道与所选期卡（窗口、倒计时、当前价） | `10:15 – 10:20 · 剩余 02:31 · $78,712` | 5 分钟市场上，看盘口 / 历史时最需要知道的是"这期还剩多久、现在涨方还是跌方领先"，不是标题。不吸顶整条轨道（再占 44px，屏幕太挤），只把所选期的一行状态收进导航；倒计时在导航里继续走。点它回到顶部 |
| **DEX 代币详情** | 导航已是 symbol + "名称 · 链"；滚走的是大字价格 + 24h 涨跌 | `$0.4312 · +3.2%`（替换"名称 · 链"） | 行情类 App 的通行做法：滚下去看图表 / 挂单时价格常驻导航；涨跌颜色沿用 |

变体实现只是把 `compact` 换成一行文字（可带颜色），组件不变。

### 4.3 不做标题折叠，但值得钉住筛选行（另一种需求）

| 页面 | 现状 | 分析 | 建议 |
| --- | --- | --- | --- |
| **预测列表页签** | 标题行 + 搜索框 + 分类 chip + 状态 chip + 排序 chip，四行约 200px 在滚动里 | 列表页滚走后用户要的不是标题而是**筛选**：换分类、切"已结束"时得滚回顶部 | 分类 chip 行滚过导航后吸顶（一行 36px），标题 / 搜索 / 其它 chip 滚走；搜索改为吸顶行右侧一个放大镜图标。这是"钉住筛选"不是"折叠标题"，另立一项 |
| **DEX 行情页签** | 标题行 + 链 / 分类 chip | 同上 | 同上，与预测列表共用实现 |
| **首页 / 资产页签** | 标题行 + 大字总资产 | 滚下去看币种列表时总资产还在会更好，但列表通常不长，收益有限 | 二期可选：折叠后导航显示"资产 · $12,345"（隐藏余额时显示 ••••••） |

### 4.4 维持现状（固定短标题已经是最合适的）

持仓、排行榜、结算进度、启用引导、划转 / 发送 / 记录、钱包与设置各页：标题本来就在导航里且不变，内容里没有会滚走的"身份区"，
折叠反而多一层状态。排行榜的周期 Tabs 吸顶收益小（列表 20 行），不做。

## 5. 一致性规则

1. 全 App 只有一种折叠时序（§2.2 的三段插值、24px 过渡距离、44px 导航高度、1px 细线），由 `CollapsingHeader` 统一；页面只决定折叠后导航中间放什么。
2. 折叠态永远保留返回键与右侧动作的位置；变化只发生在导航中间。
3. 折叠后导航中间的内容必须是"滚下去之后最需要看到的那一条"：详情 = 标题，周期市场 = 本期状态，代币 = 价格，列表 = 筛选。
4. 点击折叠态导航中间 = 回到顶部。

## 8. 首页"热门预测"横滑的可感知性（同批加做）

**问题**：热门预测卡用 `SnapCarousel fullWidth`，一张卡占满整行，下一张完全看不见；没有任何线索说明这里能横滑，用户只当它是一张静态卡。

**方案**：
- **露边**：卡片宽 = 视口 − 44，下一张露出 44px（`peek`）。这是最强的线索——看得见"后面还有"。滚到最后一张时右侧留同样的空。
- **页点**：轮播下方一排页点，当前页加长成 16px 胶囊，其余 6px 圆点；由滚动位置驱动切换（UI 线程算页码，只在页码变化时回 JS）。
- **保留"查看全部 ›"**：标题行右侧的入口不变，页点解决"能滑"，入口解决"想看完整列表"。
- 骨架态同样露边，加载中就能感知形态。
- 页点对读屏隐藏（轮播本身已有"左右滑动浏览"的 hint）。

组件改动：`SnapCarousel` 增 `peek` / `showDots`，其它使用处不受影响。

## 9. 实现与验证（2026-09-09）

- 组件：`design-system/collapsing-header.tsx`（`CollapsingHeader` + `CollapseAnchor` + `headerProgress`）。阈值不是包一层"英雄区"去测，而是页面在身份区正下方放一个零高度的 `CollapseAnchor`（内容容器的直接子元素，onLayout 的 y 即阈值），页面结构不用重排。
  `footer` 槽放滚动区之外的底部操作栏与底部面板。
- 接入：事件详情（分类小字 ↔ 图标 + 标题）、系列页（大标题 ↔ 标题 + "窗口 · 倒计时 · 当前价"，颜色随涨跌方向）、代币详情（符号 + "名称 · 链" ↔ 符号 + 价格 + 24h）、
  预测列表与 DEX 行情（悬浮条 = 分类 / 链 chip 行，预测列表右侧放大镜回到搜索框）、首页与资产页（悬浮条 = "资产 · 总额"，隐藏余额时 ••••••）。
- 单测：`headerProgress` 区间；组件展开态可见、紧凑态对读屏隐藏（默认查询找不到，`includeHiddenElements` 找得到）；floating 模式没有 `collapsed` 不渲染悬浮条。
  reanimated 替身补 `useAnimatedReaction`（惰性）与带 `scrollTo` 的 `ScrollView`。全量 jest 107 套 738 例、lint、typecheck、format 通过。
