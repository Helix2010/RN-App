# ADR-0002：使用 expo-crypto 校验远程语言包

- 状态：Accepted
- 日期：2026-08-26

## 决策

RN-App 使用 Expo SDK 57 对应的 `expo-crypto` 计算远程语言 JSON 的 SHA-256。语言包下载后必须先通过结构校验、语言编码校验、大小校验、SHA-256 校验和租户校验，再写入 AsyncStorage；任一项不过就继续使用旧缓存（同样要过租户校验）或内置语言包。

**这道校验保证的是"与 bootstrap 指针一致"，不是"这份文案确实出自本租户"**（安全评审 N27）。sha256 由同一次 bootstrap 响应下发，能改 bootstrap 的一方就能同时改摘要；它挡的是传输损坏、CDN 串包、缓存投毒，挡不住服务端本身被攻陷。真实性要靠离线签名，目前没有。为此客户端额外把首次接受的语言包 `tenantId` 钉在本机，之后只接受同一租户的包——整套 UI 文案（金额单位、风险提示、按钮语义）被换掉的影响足够大，值得在没有签名之前先加这道约束。

## 原因

Hermes/React Native 不保证始终提供 Web Crypto `subtle`，自行维护 SHA-256 会增加安全与测试负担。`expo-crypto` 有 Expo 原生适配，体积和原生影响可控，且只用于完整性校验，不存储任何密钥。真实性（离线签名）另需密钥分发与轮换方案，不在本 ADR 范围。

## 影响

新增原生依赖，首次接入需要 Development Build；语言文案变更仍可通过远程资源发布，不改变原生 ABI，因此语言包更新本身仍可走服务端资源刷新。
